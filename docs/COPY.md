# Mindough 界面文案

界面上的每一个字都按这份文档写。新加或改动文案时先查术语表；术语表里没有的词，按“语气原则”写，写完补进来。

## 语气原则
- **简洁**：一句话说完一件事；能用 4 个字就不用 8 个字。按钮用动词（「添加」「完成」「重新打开」），不加“请”“点击”。
- **口语但不随便**：像一个靠谱的朋友在旁边提醒，不卖萌、不用网络用语、不加感叹号堆砌；空状态给一句安心或下一步（「没有要先做的事，随时可以开始。」）。
- **不用技术术语**：界面上不出现 FS、DAG、markdown、正文、节点、依赖、墓碑、OPFS、wasm、里程碑代号（M1 / M2）这类词。实现细节写在代码注释和 docs 里，不写在界面上。
- **说结果，不说机制**：「已删除」而不是“已删除（墓碑保留，同步后各端一起删除）”；「数据先存在这台设备上，离线也能用」而不是“本地优先，界面永不等待网络”。
- **自动保存不用提**：所有改动都会自动保存，不要写“离开输入框自动保存”之类的说明。
- **提示放进提示里**：写法提示（Markdown 语法）只放在 ? 图标的悬停提示里，不在输入框下面写一整句。
- **数量词**：任务用「件」（「还在等 2 件事」），打卡用「次」（「已连续 5 次」），人用「位」或省略。
- **HTTP 状态码**：出现时一律附中文说明，如「503 服务不可用」「408 请求超时」。
- **标点**：中文全角标点；引用任务名用「」；数字和中文之间留半角空格（「每次 10 分钟」）。

## 写在代码里的约定
- 完成方式的名称与一句话说明在 `packages/core/src/types.ts`（`COMPLETION_MODE_LABEL`、`COMPLETION_MODE_HINT`），界面一律从这里取，不要自己写。
- 把属性说成人话的函数在 `packages/core/src/describe.ts`（`describeCompletion`、`countdownPhrase`、`friendlyDate`、`formatTarget`）；`describeRecurrence` 在 `recurrence.ts`。
- 资料库的叫法（库名、短名、选择框占位、量词）在 `packages/core/src/library.ts` 的 `LIBRARY_COPY` / `libraryCopy()`，界面从这里取。
- 内部枚举值（`once` / `timer` / `count` / `countdown`，状态 `待办` / `进行中` / `完成` / `关闭`，派生状态 `可开始` / `被阻塞`）不随文案改。
