# 多类型与多资料

一件任务能挂好几个类型，也能挂好几条资料，资料可以来自不同的库。比如「周末和小林窝在家：先看片，再一起打游戏」挂了观影、游戏、社交三个类型，资料是《奥本海默》《双人成行》和小林。

## Rei 定的

2026-10-28 Rei 定了三条：

1. **类型和资料库平级，互不连接。** 「类型是类型，资料库是资料库，是平级的。」类型不决定能挑哪个库，挑资料也不改类型。
2. **任务和类型多对多。** 一件任务挂几个类型都行，一个类型下面有很多任务。
3. **任务和资料多对多，可以跨库。** 「一个任务可以连多个资料库的资料，例如：可以同时几个人和一部电影。」

另外，类型选择器做成能搜索的多选下拉。

## 用起来是什么样

### 类型

- 详情里的「类型」胶囊写出全部类型，用顿号隔开：「观影、游戏、社交」。
- 点开是多选下拉：已选的在输入框里排成小标签，标签上有 ×；下面按大类列出全部类型，每行前面一个勾选框。
- 点一行勾上，再点去掉，下拉不收起。输入字就搜，拼音首字母也行（`yd` 找到「运动」），回车勾上第一个。输入框空着时按退格，去掉最后一个标签。
- 底部「管理类型…」去侧栏「管理 → 类型」页。
- 新建面板、项目里用的是同一个下拉。

### 资料

- 详情里，胶囊行下面是「资料」区：按库分组，库名一行，下面一条资料一行。人物算人物库的资料，排在最后。
- 每个库下面接着这个库的任务字段（看到哪、进度、读到第几页…）。人物库不显示任务字段。
- 点一条资料弹出资料卡，能编辑资料、去库里看。行尾 × 只是解开关联，资料还留在库里，提示里能撤销。
- 最下面「添加资料」打开挑资料的面板：
  - 顶上一排库按钮：「全部」、影视、游戏、书籍……人物。按钮多了就折行。
  - 选「全部」时跨库搜库里已有的资料，每条下面写着它在哪个库。
  - 选某个库时，就是原来的资料选择框：模糊搜、在线找（TMDB、Steam、Open Library 等）、新建「xxx」。
  - 点一条挂上、再点一下去掉，面板不收起。
- 一条资料都没挂时，资料区不出现，「+」菜单里有「资料」。
- 原来的「资料库」「和谁有关」两个胶囊合进了「资料」，没有了。

### 列表

- 任务行下面一行元信息写第一个类型和第一条资料，其余的数一下：`观影 · 奥本海默 +3`。
- 卡片的封面、版式跟着第一条资料所在的库走。

### 打卡、倒数日、类型页

- 按类型筛选：挂了这个类型就算。
- 按类型分组：只放在第一个类型下面，不重复出现。
- 类型页列出挂了这个类型的全部任务。

## 数据

- 新加两张表，迁移 v12：
  - `task_category`：一行是一对「任务 + 类型」。
  - `task_item`：一行是一对「任务 + 资料」，资料来自哪个库都行。
- 两张表的行 id 由这一对算出来，两台设备各自挂上同一对，得到的是同一行，按 LWW（谁后写听谁的）合并。去掉是打墓碑，再挂上就是同一行翻回来。
- 人物还用原来的 `task_person` 表，界面上算进「资料」。
- 升级时，老任务的单值（`category_id`、`library_item_id`）补进新表，当第一个。
- 任务上的单值继续写：`category_id` = 第一个类型，`library_item_id` = 第一条资料，`type_id` = 第一条资料所在的库。一条资料都没有时 `type_id` 不动（老任务只选了库、没选资料）。
- 同时写 `task.refs_mirror`，记下单值的签名。旧客户端只存它认识的列，推上来的任务行没有这个签名，或者签名对不上，就认出是旧客户端改的（见下面「待确认」第 2 条）。
- 代码：`packages/core/src/task-refs.ts`，Store 的 `categoryIdsOfTask`、`setTaskCategories`、`itemIdsOfTask`、`setTaskItems`、`toggleTaskRef`、`taskRefs`、`refLibraries`。测试：`packages/core/test/task-refs.test.ts`。

## 待确认

下面几条是我替 Rei 定的，Rei 看一下，不同意就改。

1. **人物继续用 `task_person`。** 没有并进 `task_item`。这张表本来就是多对多，旧客户端也认，挪过去要多一次迁移、两边双写，好处不大。界面上人物和别的资料放在一起，看不出区别。
2. **旧客户端改单值：只加不删，清空不生效。** 旧客户端（alpha.8 及以前）只认单值。它把类型或资料改成别的，新的那个补进多值，排第一，原来的几个都留着；它把类型清空、把资料去掉，多值不动。这样旧客户端改不丢新客户端挂的东西，代价是在旧客户端上去不掉。
3. **同 key 的任务字段跨库共用一个值。** 比如两个库都有「进度」字段，key 一样，详情里只出现一次，值也只有一份。key 不同的各管各的。
4. **打卡、倒数日按类型分组时只放第一个类型；筛选挂了就算。** 分组时一件任务出现好几次太乱，所以只放第一个；筛选时它挂着这个类型就该出来。
5. **项目的默认资料库照旧。** 在项目里新建任务，资料面板先打开项目的默认资料库，正文模板、任务字段也按它来；挑了资料以后按资料所在的库。
6. **「全部」页不能在线找、不能新建。** 跨库搜时不知道该去哪个站点找、新建到哪个库，所以要先在上面选一个库。
7. **新建任务时挑第一条资料，空正文套库模板，完成方式用库默认。** 正文还空着才套模板，完成方式没手动选过才换成库的默认；写过、选过的不动。挑第二条、第三条不再套，人物也不算。

## 删掉的旧说法

这些说法以后不成立了，PRODUCT、COPY、PLAN 里已经改掉：

- 「资料库每类型一个」「任务上直接选资料库」：任务不再选一个库，直接挑资料。
- 「改类型清空资料」「换资料库会清空原来的资料」：类型和资料无关，换类型不动资料。
- `changeTaskType`、`setTaskItem`、`TypeGrid`、`PeopleList` 这几个删了。
