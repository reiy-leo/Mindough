# Mindough 日记功能方案（待 Rei 审核，2026-10-17）

Rei 2026-10-17：「加入日记功能，先写计划，让我审核」。本文只是方案，**审过之前不写代码**。每条「待 Rei 决定」都给了推荐，见第 12 节。

## 1. 目标与不做的事

**目标**：每天随手写几句，回头能按日子翻；写的时候顺手看到「这一天做了什么」（完成的任务、打卡），不用自己再抄一遍。和任务一样：本地优先、离线能写、多端同步、能导出成 Markdown。

**不做**（至少 MVP 不做）：
- 不做社交、分享、公开日记；不做 AI 总结 / 情绪分析。
- 不做标签体系（Mindough 本来就没有标签，导入时 `#标签` 原样留在文字里，同 EXPORT.md 决定 4）。
- 不做天气、定位、录音、视频（天气要定位 + 联网接口，和「离线能写」冲突；以后再说）。
- 不做端到端加密、不做应用锁（应用锁放后续可选，见第 10 节）。
- 日记不是任务：没有状态、不进关系图、不参与「可开始 / 还不能开始」、不进我的一天清单。

## 2. 核心设计（推荐）

1. **一天一篇**（推荐）。理由：日记的天然单位是「这一天」；月历、那年今日、导出成 `YYYY-MM-DD.md` 都一一对应；和 Obsidian 每日笔记同构。一天想记几次：工具栏「插入时间」在光标处插一行 `**14:30**`，不拆成多条。
   - 对比「一天多条」（Day One 式）：每条新行，同步天然不冲突；但月历要聚合、导出要多文件、列表变碎。代价比收益大，不推荐。
2. **id 由日期确定**（同 `taskLinkId` / `prefId` 的做法）：两台设备离线各自开了「今天」那篇，同步后还是同一行，不会出现两篇 10-17。删了再写回同一天也是同一个 id（墓碑翻回来）。
3. **内容 = Milkdown markdown**，和任务内容同一个编辑器、同一套工具栏（标题、清单、提示块、公式、折叠块…都能用）；插图走现有上传（登录在线进 R2，离线 data:）；网络图片同样只显示成文字（PRODUCT 第 12 条）。
4. **「这一天」只读侧栏**：自动列出当天完成 / 关闭的任务、打过的卡（次数 / 时长）、当天新加的资料；**只是算出来显示，不写进日记内容**（不污染 markdown、不制造同步改动）。想留进日记就点一行「插入」，变成一个链接。
5. **可选字段只留「心情」一个**（5 档，可不填）。不做标签、天气、地点。
6. **入口**：侧边栏「今天」小节加「日记」；我的一天页底部一张「今天的日记」小卡（没写时「写几句今天的事」，写了显示第一行）。
7. **同步沿用整段后写赢，但日记加一道保护**：两台设备都改了同一天且内容不同时，不静默丢掉一边，而是把输掉的那版收进末尾一个折叠块「另一台设备上同时写的」。M5 正文逐字合并做好后，日记直接用它，这道保护去掉。
8. **导出 `journal/YYYY/MM/YYYY-MM-DD.md`**，front matter 只放 id、date、mood；导回来按 id 认。

## 3. 入口（侧边栏 / 我的一天 / 手机）

- 桌面侧边栏「今天」小节：我的一天 · 待安排 · 打卡 · 可做 · **日记**（图标 lucide `BookOpen` 或 `NotebookPen`）。
- 我的一天：清单下面一张「今天的日记」卡（第一行预览 + 心情图标；点开进日记页今天那篇）。可在设置里关掉这张卡。
- 手机标签栏仍是 4 个 + 更多（我的一天 · 待安排 · 打卡 · 列表）：日记放进「更多」的「今天」组；入口主要靠我的一天那张卡。（要不要换掉某个标签见第 12 节 Q3。）
- 新建浮动按钮（FAB）不改：日记页上 FAB 仍是新建任务；日记页自己顶部有「今天」按钮。
- ⌘K：「写今天的日记」命令；搜索结果里有日记（见第 7 节）。

## 4. 日记页与回顾

**桌面**（宽屏两栏）：
- 左栏：月历（周一开始，跟随系统区域）。有日记的日子一个小点，填了心情就用心情的颜色；今天描边；点哪天开哪天（过去、将来都能写，将来的日子提示「这天还没到」但照样能写——比如提前写计划，行为同普通一天）。月历下面是这个月的列表（日期 + 第一行 + 字数）。
- 右栏：日期大标题「10 月 17 日 星期六」+ 心情 5 档 + 编辑器；最右窄栏（或编辑器下方折叠）是「这一天」只读汇总。
- 「那年今日」：今天那篇下方，有往年同月同日的日记时出一行「1 年前的今天」「2 年前的今天」…，点开在侧边看（只读，可跳过去改）。没有就不显示（不写空状态）。

**手机**：
- 进来是今天那篇（全屏编辑，顶部日期可点 → 月历弹层选日子）；左上「‹」回列表（倒序，按月分段）。
- 「这一天」收成编辑器上方一条胶囊「完成 3 件 · 打卡 2 次」，点开看详情。

**以后（J3）**：写日记的天数热力图（复用 `heatmap.ts`，和打卡页一个样子），连续写了几天。

## 5. 和任务 / 打卡 / 资料 / 人物的关联

| 关联 | MVP | 后续 |
|---|---|---|
| 当天完成 / 关闭的任务（按 `done_at` 本地日期） | ✅ 只读列表，点开任务详情 | — |
| 当天打卡（`check_in.at` 本地日期，按任务汇总：几次 / 多少分钟 / 计数多少） | ✅ 只读 | — |
| 当天新加的资料（`created_at`） | ✅ 只读（看完 / 读完一本在这能看到） | — |
| 当天我的一天里没做完的 | 不显示（日记不是复盘清单） | 视反馈 |
| 引用任务 / 资料 / 人物 | 「这一天」一行旁「插入」→ 写成 `[第一行](mindough://task/<id>)` 链接 | J2：打 `@` 弹出挑选（复用 TaskSearch / LibraryPicker），编辑器里显示成小胶囊；任务 / 资料 / 人物详情里出「在日记里提到」反向列表 |

- 引用就用深链接写在 markdown 里（`mindough://task/…`、`mindough://library/movie/…`、`mindough://person/…`），不加关联表：导出到 Obsidian 也是一个看得懂的链接；反向列表由扫描内容算出（量小，够快）。
- 点日记里的这种链接 = app 内跳转，不交给系统浏览器（`lib/external.ts` 放行 `mindough:`）。

## 6. 心情等可选字段

推荐最小集：**只有心情**，5 档，可不填、可再点一次取消：

| 值 | 中文 | English | 图标（lucide） |
|---|---|---|---|
| 1 | 很糟 | Awful | `Angry` |
| 2 | 不太好 | Bad | `Frown` |
| 3 | 一般 | Okay | `Meh` |
| 4 | 不错 | Good | `Smile` |
| 5 | 很好 | Great | `Laugh` |

颜色进皮肤令牌（三套 × 明暗）。月历小点用心情色。字数只显示不存（「312 字」，英文按词数）。

## 7. 搜索与 ⌘K

- `search.ts` 的 `SearchHit` 加 `kind: 'journal'`（标题 = 「10 月 17 日」，片段 = 命中附近的文字，沿用 `snippetAround`）；排在任务后面。
- ⌘K 命令「写今天的日记」；输入日期（`10-17`、`2026-10-17`、「昨天」）直接跳到那篇。
- 日记页顶部有自己的搜索框（只搜日记，按日期倒序）。
- 隐私选项「搜索里不显示日记」见第 10 节。

## 8. 提醒

- 设置 → 提醒 加一行「每天提醒写日记」：开关 + 时间（常用 21:00 / 22:00 / 23:00 + 其他时间），默认关。
- `reminders.ts` 加 `ReminderKind = 'journal'`：每天那个时间，**当天已经写了（内容非空）就不响**。通知「今天过得怎么样？写几句吧」，点了打开今天那篇。手机照现有做法交给系统排 48 小时。
- 提醒时间存同步的 pref（`journal.remind_time`，跟着账户走）；响没响、稍后存本机（同现有提醒）。

## 9. 同步与冲突

- 新表 `journal_entry` 走现有 outbox + 游标 + 行级 LWW，云端不用改（云端只存整行 JSON）。
- **整段后写赢的问题**：任务内容被覆盖还能重写，日记被覆盖就没了。所以 MVP 加一道只给日记的保护：
  - `applyRemote` 收到一篇日记时，如果本机这一行还在 outbox 里没推（本机也改过）、且两边内容不同：不直接取赢家，而是 **赢家内容 + 末尾一个折叠块**：`<details><summary>另一台设备上同时写的 · 10-17 14:30</summary>…输家内容…</details>`，作为一次新写入（新 HLC）推上去。已经包含的那段不重复（复用 `merge.ts` 的 `mergeNotes` 思路），两台同时合也会收敛。
  - 心情字段照常 LWW（丢了能再点）。
  - 这道保护只在「两边都离线改了同一天」时触发，日常一台设备写不会出现。
- **衔接 M5**：M5「正文逐字合并（CRDT）」做好后，任务内容和日记内容一起换过去，上面的保护去掉；`body_md` 列名保持一致就是为了到时少改。
- 不推荐现在就为日记单独上 CRDT：工作量等于提前做 M5 的一半，而日记基本是一台设备在写。

## 10. 隐私（可选，不进 MVP）

日记比任务私密。分两档，都放到 J3 再做：
- **轻**（推荐先做这个）：设置 → 日记「搜索里不显示日记」「我的一天不显示日记预览」「导出时包含日记」三个开关。纯界面，几行代码。
- **重**：应用锁（打开日记页要面容 / 指纹 / 系统密码；Web 用一个本机密码）。原生要接各平台生物识别插件（Tauri biometric 只支持手机），桌面要另想；工作量大，等 Rei 说要再做。
- 说明一下现状：日记和任务一样，明文存在本机和云端库（Turso / D1），只有 Rei 的账号能读。要「云端也看不见」得做端到端加密，不在本方案内。

## 11. 导入导出

**导出**（EXPORT.md 加一节）：

```
journal/
  2026/
    10/
      2026-10-17.md
```

```markdown
---
id: 0192a0e4-1c00-7000-8002-000000000000
date: 2026-10-17
mood: 4
created: 2026-10-17T13:02:11.000Z
---
今天把日记方案写完了。

**21:40** 散步回来……
```

- 文件夹名固定 `journal/`（同 `library/`、`people/`、`assets/` 这些固定的英文名；组名撞了加「 2」）。图片照现有规则进 `assets/`、正文里改成相对路径。
- 「这一天」汇总不导出（是算出来的）。
- **导入**：
  - 自己的格式：按 id 认，规则同任务（新建 / 跳过 / 可选覆盖、整批撤销）。
  - 普通 markdown 文件夹：文件名正好是 `YYYY-MM-DD.md` 的（任何层级，含 Obsidian 每日笔记），导入预览里给一个开关「把按日期命名的文件当日记」（默认开）；同一天已有日记时，默认跳过、可选「接在后面」。
  - **Day One**（J3 可选）：Day One 导出的 zip（`Journal.json` + `photos/`）→ 每条按本地日期并进那一天（一天多条按时间顺序拼，每条前插时间行），图片进 assets，心情 / 标签 / 天气丢弃（标签写成文字行尾）。其他日记 app（如「格志」「moo 日记」）先不支持，Rei 有具体要导的再看格式。

## 12. 待 Rei 决定（每题带推荐）

1. **一天一篇还是一天多条？** 推荐 **一天一篇**（+「插入时间」）。理由见第 2 节第 1 条。
2. **英文名？** 推荐 **Journal**（Apple Journal、Day One 都这么叫；Diary 偏「私密日记本」、口气幼一点）。代码 / 路由 / 深链 / 导出文件夹统一用 `journal`。（任务里写的 `diary/…` 也可以，选定一个全处统一。）
3. **入口放哪？** 推荐侧边栏「今天」小节最后 + 我的一天底部小卡；**手机标签栏不动**，日记在「更多」里。备选：用「日记」换掉手机标签栏的「列表」。
4. **可选字段？** 推荐 **只要心情**（5 档）。要不要天气 / 地点 / 标签？推荐都不要。
5. **凌晨写算哪天？** 推荐 **按 0 点分**，但 0–4 点打开日记时顶部提示「还在写昨天的？」一键切到昨天那篇。备选：设一个「一天从几点开始」（默认 4 点），整个日记都按它算。
6. **「这一天」汇总放哪些？** 推荐：完成 / 关闭的任务 + 打卡 + 新加的资料；都只显示、不写进日记。要不要「插入」把它们一键变成文字列表？推荐只给单行「插入」，不给「全部插入」（免得日记变流水账）。
7. **同步保护**：推荐 MVP 就做「两边都改时保留另一版到折叠块」，M5 再换成逐字合并。备选：完全按整段后写赢（会丢字）。
8. **导出文件夹** `journal/YYYY/MM/YYYY-MM-DD.md`，推荐按年 / 月分两层（Obsidian 里好翻）；备选平铺 `journal/YYYY-MM-DD.md`。
9. **隐私**：推荐 J3 只做三个开关（搜索里不显示、我的一天不显示预览、导出含不含）；应用锁等 Rei 说要再做。
10. **提醒**：默认关，推荐默认时间 21:00；当天写过就不响。
11. **将来的日子能不能写？** 推荐能写（当计划 / 备忘也行），月历上照常显示。备选：只能写今天和以前。

## 14. 数据表草案与迁移

SQLite 迁移 **v6**（当前 main 最新是 v5「资料合并」；动工前再确认没有别的分支占了 v6）：

```sql
CREATE TABLE IF NOT EXISTS "journal_entry" (
  "id" TEXT PRIMARY KEY NOT NULL, "updated_at" TEXT NOT NULL, "deleted" INTEGER NOT NULL DEFAULT 0,
  "date" TEXT NOT NULL,              -- 本地日期 YYYY-MM-DD
  "body_md" TEXT NOT NULL DEFAULT '',
  "mood" INTEGER,                    -- 1–5，可空
  "created_at" TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS "journal_entry_date" ON "journal_entry" ("date");
```

- `types.ts` 加 `JournalEntry`，`TABLES` / `COLUMNS` 加 `journal_entry: { date: 'text', body_md: 'text', mood: 'int?', created_at: 'text' }`（COLUMNS 的类型约束会逼着两边一致）。
- id：`journalEntryId(date)`——UUIDv7 形状，时间戳段 = 这一天 00:00 UTC 的毫秒数，第四段固定 `8002`（打卡分类用的是 `8001`），其余为 0；各设备算出来一样。
- 不加列到别的表；引用靠内容里的深链接，「在日记里提到」靠扫描。
- pref 新键：`journal.remind_time`、`journal.myday_card`（以及 J3 的隐私开关）。
- localStorage / 内存适配器、`migrate.ts`、导出 `_meta/mindough.json` 的 counts 加上日记数。
- 云端不用改。旧版本客户端拉到 `journal_entry` 行能存不能用，不影响别的。

core 新模块 `journal.ts`（纯函数 + 测试）：`journalEntryId`、`daySummary(date, tasks, checkIns, items, tz)`、`onThisDay(entries, date)`、`mergeJournalConflict(winner, loser, at)`、`isJournalFile(path)`（导入）；Store：`journalOf(date)`、`setJournalBody`、`setJournalMood`、`deleteJournal`、`journalDays(month)`。
